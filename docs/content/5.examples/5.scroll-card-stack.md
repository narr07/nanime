A stack of playing cards, each one showing a suit, sits still until you
scroll the box. Then it fans out into a hand of cards, each one landing at
its own angle, timed to the scroll position rather than the clock.

## What's happening

Scroll down inside the box and the stacked cards spread apart, rotating
into a fan. Scroll back up and they collapse into the stack again. The
motion tracks the scrollbar directly: stop halfway and the cards stop
halfway too. On a wide screen the cards fan out sideways. On a narrow one
they drop in from above and stack at an angle instead.

## How it's built

Each card face is a `SuitIcon` subcomponent, an inline SVG cycling through
spade, heart, diamond and club, built from basic shapes (a path, a polygon,
three overlapping circles) rather than an icon font or an image file. That
keeps the deck self-contained: nothing to fetch over the network, and
nothing that can fail to load.

[`useAnimate`](/composables/use-animate) drives the fan, targeting every
`.oss-card` at once with staggered `rotate`, `x` and `y` values so each
card starts its move slightly after the last.

The scroll link comes from Anime.js's `onScroll`, imported from
`animejs/events` and passed straight into `autoplay`. A `ScrollObserver`
assigned to `autoplay` calls `.link()` on the animation itself once it
exists, so this is the same wiring as `onScroll(...).link(animation)`
without holding a separate reference to link by hand. `container` and
`target` are both CSS selectors, `.oss-viewport` and `.oss-track`, so the
observer measures scroll against the demo's own scrolling box instead of
the whole page. `sync: 0.1` smooths the mapping from scroll position to
animation progress instead of jumping frame to frame.

Which set of values plays, the sideways fan or the vertical drop, comes
from [`useMediaQuery`](https://vueuse.org/core/useMediaQuery/){target="_blank"}
watching `(orientation: landscape)`. `useAnimate` only rebuilds its
animation when the target passed to it changes, so reading the media query
inside the function passed as its second argument picks a variant once,
the first time the target resolves after mount, rather than reactively
swapping variants on every resize.

## Building it yourself

1. Build the deck: an outer scrollable box, a tall inner track to give the
   scroll distance, and a `position: sticky` stage inside the track so the
   cards stay put while the track scrolls past.
2. Stack the cards absolutely inside the sticky stage, all at the same
   spot, each carrying a shared class like `.oss-card`. Give each one a
   face: an inline SVG built from basic shapes, not an icon font or an
   `<img>`, so the deck never depends on a network request that can fail.
3. Read `useMediaQuery('(orientation: landscape)')` and branch: build a
   sideways fan-out object (`x`, `y`, `rotate`, each staggered) for
   landscape, and a vertical drop-in object for everything else. Type both
   as `AnimationParams` from `#nanime/types`, the project's strict
   TypeScript setup otherwise infers the portrait variant's `rotate.from`
   callback as implicit `any`.
4. Call `useAnimate('.oss-card', () => ({ ...variant, autoplay: onScroll({ container, target, enter, leave, sync }) }))`.
   `useAnimate` is auto-imported by the nanime module, the same as every
   other composable on this page, so it needs no import statement of its
   own. Wrapping the parameters in a function defers reading the media
   query and calling `onScroll` until the target has actually mounted.
5. Point `onScroll`'s `container` and `target` at the scroll box and the
   tall track, not the window, so the effect is scoped to the demo instead
   of hijacking the page's own scroll.
