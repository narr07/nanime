## What's happening

The ground line traces itself in first. Once it's drawn, the character
starts walking along it, rising and dipping with the curve of the path and
bouncing a little on each step. When it reaches the far end it turns back
and retraces the same line to where it started, then repeats.

## How it's built

The path itself is one hand-drawn `<path>` element, a double curve so the
walk has an uphill and a downhill section. It carries both a template ref
and an `id="walk-path"`, two separate ways of pointing at the same
element for two separate needs: the ref is how `useAnimate`'s own target
finds it, the id is how `createMotionPath`'s CSS selector finds it below.
Giving it only one of the two is a real bug, not a style choice, a ref
alone leaves `createMotionPath('#walk-path')` with nothing to select.
[`useAnimate`](/composables/use-animate) draws the path in by reading its
real length with `getTotalLength()` and animating `strokeDashoffset` from
that length down to `0`, the standard SVG line-draw technique. That length
can only be read once the `<path>` exists in the DOM, so it's read inside
the function passed as `useAnimate`'s second argument rather than at setup
time, the same reason a media query or `onScroll` selector would need to
be deferred that way.

Movement along the path comes from `createMotionPath`, imported from
`#nanime/proxies/svg`. Called with `#walk-path`, it returns `translateX`
and `translateY` values that trace the path's exact coordinates, so
spreading them into `useAnimate('.walker', ...)`'s parameters moves the
character group along the line. `direction: 'alternate'` makes it walk the
path forward, then backward, rather than snapping back to the start on
every loop. `createMotionPath` also returns a `rotate` value that tilts a
target to match the path's tangent, left unused here so the character
stays upright instead of banking with the slope.

The step bounce and the walk itself are two separate animations on two
nested groups, `.walker` (the motion path) and `.walker-bounce` (a small
looping `translateY`) inside it, so they don't fight over the same
property. The head adds a third layer: `morphTo`, also from
`#nanime/proxies/svg`, morphs the head into a hidden target shape at the
same spot and back, an easing squash that reads as a bit of weight landing
on each step. Both shapes are drawn as `<path>` elements, a circle and an
ellipse each written as two arc commands rather than as native `<circle>`
and `<ellipse>` tags, because `morphTo` throws if either side isn't a
`<path>`, `<polygon>` or `<polyline>`: it works by writing new coordinates
into that element's `d` or `points` attribute, which only those three tags
have.

The legs themselves don't move. Between the bounce, the squash, and the
walk along the path, the figure reads as walking without needing
per-leg articulation.

## Building it yourself

1. Draw a single `<path>` for the ground. Give it both a template ref
   (for `useAnimate`'s own target) and `id="walk-path"` (for
   `createMotionPath`'s CSS selector) since they resolve the element two
   different ways.
2. Animate that ref's `strokeDashoffset` from its `getTotalLength()` down
   to `0` to draw it in. Read the length inside `useAnimate`'s second
   argument as a function, not before the element exists.
3. Group the character in nested `<g>` elements: an outer one for the walk,
   an inner one for the step bounce, so a per-target property (`translateY`
   on each) never gets overwritten by the other animation.
4. Call `useAnimate('.walker', () => ({ ...createMotionPath('#walk-path'), ...}))`,
   destructuring `translateX` and `translateY` (skip `rotate` to keep the
   character upright) with `direction: 'alternate'` so it walks the path
   both ways instead of jumping back to the start.
5. Animate the inner bounce group's `translateY` as a small independent
   loop for the step.
6. Draw the head and its hidden morph target as `<path>` elements (a
   circle and an ellipse, each as two arc commands), not `<circle>` or
   `<ellipse>` tags. `morphTo` only accepts `<path>`, `<polygon>` or
   `<polyline>`, since it writes the morphed shape into `d` or `points`.
   Animate the head's `d` with `morphTo(targetSelector)` on a loop for a
   squash on each step.

Using the nanime Nuxt module, build a Vue 3 component where a small SVG
character walks along a hand-drawn path.

Draw one SVG with a viewBox, containing a single <path> for the ground
(a double curve, for example "M 30 140 Q 110 90 190 140 Q 270 190 350
140"). Give this path element BOTH a template ref AND id="walk-path", not
just one of the two. They serve different code below: the template ref is
what useAnimate's own target argument resolves, the id is what
createMotionPath('#walk-path')'s CSS selector resolves, and it queries the
DOM independently of the ref. Leaving off the id makes createMotionPath
find nothing and return undefined, which throws when its result is
destructured.

morphTo throws at runtime if either shape it's given isn't a <path>,
<polygon> or <polyline>, because it works by writing new coordinates into
that element's d (or points) attribute, and only those three tags have
one. So draw the head and its morph target as <path> elements, not
<circle> or <ellipse>: a circle centered at (0,-54) with radius 10 as
"M -10,-54 A 10,10 0 1,0 10,-54 A 10,10 0 1,0 -10,-54 Z", and an ellipse
at the same center with rx 13, ry 7 as
"M -13,-54 A 13,7 0 1,0 13,-54 A 13,7 0 1,0 -13,-54 Z" (two arc commands
each, the standard way to draw a circle or ellipse as path data). Add the
ellipse path hidden (opacity 0) in the same SVG, to serve as the morph
target. Build the character as nested <g> elements: an outer .walker
group for movement along the path, containing an inner .walker-bounce
group for the step bounce, containing static leg <line> elements, a body
<rect>, and the head <path>.

useAnimate is auto-imported by the nanime module, no import statement is
needed for it. createMotionPath and morphTo are imported from
#nanime/proxies/svg, not from the animejs package directly.

For the ground line: call useAnimate on the path's template ref, with a
function (not a plain object) as the second argument that reads
pathRef.value.getTotalLength() and returns { strokeDasharray: String(length),
strokeDashoffset: [length, 0], duration: 900, ease: 'inOutQuad' }. This
must be a function because the path element, and therefore its length,
doesn't exist until after mount.

For the walk: call useAnimate('.walker', fn) where fn is a function that
calls createMotionPath('#walk-path') inside itself (also deferred until
after mount, for the same reason) and returns an object spreading only
that call's translateX and translateY into the params, not its rotate
value, so the character doesn't tilt to match the path's slope. Add
duration: 4000, delay: 900, ease: 'linear', loop: true, and direction:
'alternate' so it walks the path forward then backward instead of
snapping back to the start each loop.

For the step bounce: call useAnimate('.walker-bounce', { translateY: [0,
-7, 0], duration: 420, delay: 900, loop: true, ease: 'inOutQuad' }), a
plain object is fine here since it references no DOM-dependent value.

For the head: call useAnimate('.walker-head', fn) where fn returns { d:
morphTo('.walker-head-squash'), duration: 420, delay: 900, loop: true,
direction: 'alternate', ease: 'inOutQuad' }. morphTo resamples both shapes
by arc length and does not require them to have the same number of points
in their original path data, but both must be <path>, <polygon> or
<polyline> elements as described above.

Do not animate the legs. The combination of the path-following walk, the
bounce, and the head squash is enough to read as walking.
